Problem: Find all unique triplets that sum to zero

Problem Statement
Given: An integer array nums
Find: All unique triplets [nums[i], nums[j], nums[k]]
Such that: i != j, i != k, j != k, and nums[i] + nums[j] + nums[k] == 0
// Example 1: Input: nums = [-1,0,1,2,-1,-4] Output: [[-1,-1,2],[-1,0,1]] // Example 2: Input: nums = [0,1,1] Output: [] // Example 3: Input: nums = [0,0,0] Output: [[0,0,0]]
Solution 1: Brute Force (DON'T USE!) ❌
O(n³) TLE
public List<List<Integer>> threeSum(int[] nums) { List<List<Integer>> result = new ArrayList<>(); Set<List<Integer>> set = new HashSet<>(); for (int i = 0; i < nums.length; i++) { for (int j = i + 1; j < nums.length; j++) { for (int k = j + 1; k < nums.length; k++) { if (nums[i] + nums[j] + nums[k] == 0) { List<Integer> triplet = Arrays.asList( nums[i], nums[j], nums[k]); Collections.sort(triplet); set.add(triplet); } } } } result.addAll(set); return result; }
Why it's bad:
❌ Time: O(n³) - Triple nested loops
❌ Space: O(n) - HashSet for duplicates
❌ Will get Time Limit Exceeded (TLE)
Solution 2: HashMap Approach 📊
O(n²) Good
public List<List<Integer>> threeSum(int[] nums) { List<List<Integer>> result = new ArrayList<>(); Arrays.sort(nums); // Sort first! for (int i = 0; i < nums.length - 2; i++) { // Skip duplicates for first number if (i > 0 && nums[i] == nums[i - 1]) continue; Set<Integer> seen = new HashSet<>(); for (int j = i + 1; j < nums.length; j++) { int complement = -nums[i] - nums[j]; if (seen.contains(complement)) { result.add(Arrays.asList(nums[i], complement, nums[j])); // Skip duplicates for second number while (j + 1 < nums.length && nums[j] == nums[j + 1]) j++; } seen.add(nums[j]); } } return result; }
Complexity: Time O(n²), Space O(n)
Uses HashSet to find complement in O(1)
Solution 3: Two Pointers ⭐ (BEST!)
O(n²) Optimal Interview Favorite
public List<List<Integer>> threeSum(int[] nums) { List<List<Integer>> result = new ArrayList<>(); // Step 1: Sort the array Arrays.sort(nums); // Step 2: Fix first number, use 2-pointer for rest for (int i = 0; i < nums.length - 2; i++) { // Skip positive numbers (optimization) if (nums[i] > 0) break; // Skip duplicates for first number if (i > 0 && nums[i] == nums[i - 1]) continue; // Two pointers for remaining array int left = i + 1; int right = nums.length - 1; while (left < right) { int sum = nums[i] + nums[left] + nums[right]; if (sum == 0) { result.add(Arrays.asList(nums[i], nums[left], nums[right])); // Skip duplicates for second number while (left < right && nums[left] == nums[left + 1]) { left++; } // Skip duplicates for third number while (left < right && nums[right] == nums[right - 1]) { right--; } left++; right--; } else if (sum < 0) { left++; // Need larger sum } else { right--; // Need smaller sum } } } return result; }
Why Two Pointers is Best:
✅ Time: O(n²) - Optimal for this problem
✅ Space: O(1) - No extra data structures
✅ Clean and easy to understand
✅ Handles duplicates elegantly
Visual Walkthrough 👁️
Input: [-1, 0, 1, 2, -1, -4]
Step 1: Sort [-4, -1, -1, 0, 1, 2] Step 2: i = 0, nums[i] = -4 i L R [-4, -1, -1, 0, 1, 2] sum = -4 + (-1) + 2 = -3 < 0, move L → Step 3: i = 1, nums[i] = -1 i L R [-4, -1, -1, 0, 1, 2] sum = -1 + (-1) + 2 = 0 ✓ Found! [-1, -1, 2] Step 4: Skip duplicate -1, i = 3, nums[i] = 0 i L R [-4, -1, -1, 0, 1, 2] sum = 0 + 1 + 2 = 3 > 0, move R ← i LR [-4, -1, -1, 0, 1, 2] sum = 0 + 1 + 1 = 0 // Wait, L not < R anymore Result: [[-1, -1, 2], [-1, 0, 1]]
Key Insights 🔑
1. Why Sort First?
  • ✅ Enables two-pointer technique
  • ✅ Makes duplicate handling easy
  • ✅ Allows early termination (if nums[i] > 0)
2. How Two Pointers Work?
  • Fix one number (i)
  • Use two pointers (left, right) for remaining array
  • If sum < 0: move left pointer → (increase sum)
  • If sum > 0: move right pointer ← (decrease sum)
  • If sum == 0: found triplet! Move both pointers
3. Duplicate Handling
// Skip duplicate for i if (i > 0 && nums[i] == nums[i-1]) continue; // Skip duplicates after finding triplet while (left < right && nums[left] == nums[left+1]) left++; while (left < right && nums[right] == nums[right-1]) right--;

🐛 Bug 4: Moving Only One Pointer After Finding Triplet
LOGICAL ERROR
// WRONG ❌ if (sum == 0) { result.add(Arrays.asList(nums[i], nums[left], nums[right])); left++; // Only moving left! // This will cause issues! }
Why it's wrong:
You've already found a triplet with this combination.
Need to move BOTH pointers to find new combinations!
// CORRECT ✅ if (sum == 0) { result.add(Arrays.asList(nums[i], nums[left], nums[right])); // Skip duplicates while (left < right && nums[left] == nums[left + 1]) left++; while (left < right && nums[right] == nums[right - 1]) right--; // Move BOTH pointers left++; right--; }
🐛 Bug 5: Not Checking left < right in While Loops
BOUNDARY ERROR
// WRONG ❌ while (nums[left] == nums[left + 1]) { left++; // Can cause IndexOutOfBoundsException! }
Problem: If all remaining elements are same:
left will keep incrementing beyond right!
// CORRECT ✅ while (left < right && nums[left] == nums[left + 1]) { left++; } while (left < right && nums[right] == nums[right - 1]) { right--; }
🐛 Bug 6: Integer Overflow
EDGE CASE
// POTENTIAL ISSUE ⚠️ int sum = nums[i] + nums[left] + nums[right]; // What if sum overflows Integer.MAX_VALUE?
For 3Sum: Usually not an issue due to problem constraints.
But if needed:
long sum = (long)nums[i] + nums[left] + nums[right];

Detailed: Two Pointers Time Complexity
// Step 1: Sorting Arrays.sort(nums); // O(n log n) // Step 2: Outer loop for (int i = 0; i < nums.length - 2; i++) { // O(n) // Step 3: Inner two-pointer loop while (left < right) { // O(n) in worst case // Each iteration moves left or right // Total iterations for all i: O(n) } } // Total: O(n log n) + O(n × n) = O(n²) // Sorting is dominated by nested loops
Why Inner Loop is O(n) Total?

For each i:
- left starts at i+1
- right starts at n-1
- They move towards each other
- Maximum movements: (n-1) - (i+1) = n-i-2

Sum for all i: (n-2) + (n-3) + ... + 1 ≈ O(n²)
Space Complexity Breakdown
// Two Pointers Approach // Variables used: int i; // O(1) int left; // O(1) int right; // O(1) int sum; // O(1) // Result list (not counted in space complexity) List<List<Integer>> result; // O(k) where k = triplets found // Total auxiliary space: O(1)
HashMap Approach Space
// For each i, create new HashSet Set<Integer> seen = new HashSet<>(); // O(n) in worst case // Total: O(n) auxiliary space
Best, Average, Worst Case Analysis
Best Case: O(n log n)
// Input: [1, 2, 3, 4, 5] (all positive) // After sorting: same for (int i = 0; i < nums.length - 2; i++) { if (nums[i] > 0) break; // Breaks immediately! } // Only sorting is done: O(n log n)
Average Case: O(n²)
// Input: Mixed positive/negative numbers // Some triplets exist // Full two-pointer search needed
Worst Case: O(n²)
// Input: [-n, -n+1, ..., -1, 0, 1, ..., n-1, n] // Many triplets exist // Must check all combinations
Why We Can't Do Better Than O(n²)?
Lower Bound Proof:

1. We need to examine all possible triplets
2. Number of triplets = C(n, 3) = n(n-1)(n-2)/6 ≈ O(n³)
3. But we use sorting + two pointers to reduce to O(n²)
4. We can't avoid checking O(n²) pairs
Key Insight:
For each fixed first element (n choices),
we must check remaining pairs (n² total pairs).
This gives lower bound of Ω(n²).

Q1: Why must we sort the array first?
Medium
Three Reasons:

1️⃣ Two Pointers Logic:
- We need to know which pointer to move
- If sum < 0: move left (to increase sum)
- If sum > 0: move right (to decrease sum)
- This only works on sorted array!

2️⃣ Duplicate Handling:
- Duplicates are adjacent after sorting
- Easy to skip: if (nums[i] == nums[i-1]) continue

3️⃣ Early Termination:
- Can break when nums[i] > 0
- Can optimize based on min/max values
Without sorting:
[2, -1, 0, 1, -4]
If sum < 0, which pointer to move? 🤔
Can't decide!

With sorting:
[-4, -1, 0, 1, 2]
If sum < 0, move left → (guaranteed to increase)
If sum > 0, move right ← (guaranteed to decrease)

Q3: What if target is not 0?
Easy Variation
// 3Sum with target public List<List<Integer>> threeSumTarget(int[] nums, int target) { List<List<Integer>> result = new ArrayList<>(); Arrays.sort(nums); for (int i = 0; i < nums.length - 2; i++) { if (i > 0 && nums[i] == nums[i - 1]) continue; int left = i + 1, right = nums.length - 1; int newTarget = target - nums[i]; // Only change! while (left < right) { int sum = nums[left] + nums[right]; if (sum == newTarget) { result.add(Arrays.asList(nums[i], nums[left], nums[right])); while (left < right && nums[left] == nums[left+1]) left++; while (left < right && nums[right] == nums[right-1]) right--; left++; right--; } else if (sum < newTarget) { left++; } else { right--; } } } return result; }
Q4: How to find closest sum to target?
3Sum Closest
public int threeSumClosest(int[] nums, int target) { Arrays.sort(nums); int closest = nums[0] + nums[1] + nums[2]; for (int i = 0; i < nums.length - 2; i++) { int left = i + 1, right = nums.length - 1; while (left < right) { int sum = nums[i] + nums[left] + nums[right]; // Update closest if this sum is closer if (Math.abs(sum - target) < Math.abs(closest - target)) { closest = sum; } // If exact match, return immediately if (sum == target) return sum; if (sum < target) { left++; } else { right--; } } } return closest; }
Q5: What if we need 4Sum? kSum?
Generalization
// 4Sum = Fix 1 element + 3Sum public List<List<Integer>> fourSum(int[] nums, int target) { List<List<Integer>> result = new ArrayList<>(); if (nums.length < 4) return result; Arrays.sort(nums); for (int i = 0; i < nums.length - 3; i++) { if (i > 0 && nums[i] == nums[i-1]) continue; // Now do 3Sum with target - nums[i] for (int j = i + 1; j < nums.length - 2; j++) { if (j > i+1 && nums[j] == nums[j-1]) continue; // Two pointers for remaining int left = j + 1, right = nums.length - 1; long newTarget = (long)target - nums[i] - nums[j]; while (left < right) { long sum = nums[left] + nums[right]; if (sum == newTarget) { result.add(Arrays.asList( nums[i], nums[j], nums[left], nums[right])); while(left < right && nums[left] == nums[left+1]) left++; while(left < right && nums[right] == nums[right-1]) right--; left++; right--; } else if (sum < newTarget) { left++; } else { right--; } } } } return result; }
Pattern:
- 3Sum: O(n²)
- 4Sum: O(n³)
- kSum: O(n^(k-1))

Q7: What's the expected number of triplets?
Probability
Expected Value Analysis:

For random array of size n:
- Total possible triplets: C(n,3) = n(n-1)(n-2)/6
- Probability that sum = 0: depends on range
- If range is [-R, R], roughly O(n²/R) triplets

For typical LeetCode constraints:
- n ≤ 3000, values in [-10^5, 10^5]
- Expected triplets: ~10-100
Q8: Can we do better than O(n²)?
Theoretical
Answer: NO!

Proof by 3SUM Hardness:
- 3SUM problem is a well-studied problem
- No known algorithm better than O(n²)
- It's conjectured that O(n²) is optimal
- This is called the "3SUM conjecture"

Why?
We must examine Ω(n²) pairs to ensure we find all triplets.
In interviews, mention: "This is optimal due to the 3SUM conjecture."
Variation 1: 3Sum Smaller
Medium
Problem: Count triplets with sum < target
public int threeSumSmaller(int[] nums, int target) { Arrays.sort(nums); int count = 0; for (int i = 0; i < nums.length - 2; i++) { int left = i + 1, right = nums.length - 1; while (left < right) { int sum = nums[i] + nums[left] + nums[right]; if (sum < target) { // All pairs (left, left+1), (left, left+2), ..., (left, right) // are valid! count += right - left; left++; } else { right--; } } } return count; }
Key Insight: If sum < target with (left, right),
then all (left, k) where left < k ≤ right are also valid!
Variation 2: 3Sum Multiplicity
Hard

public int threeSumMulti(int[] arr, int target) { final int MOD = 1_000_000_007; long count = 0; // Count frequency of each number Map<Integer, Long> freq = new HashMap<>(); for (int num : arr) { freq.put(num, freq.getOrDefault(num, 0L) + 1); } // For each unique pair (x, y) for (int x : freq.keySet()) { for (int y : freq.keySet()) { int z = target - x - y; if (!freq.containsKey(z)) continue; long fx = freq.get(x); long fy = freq.get(y); long fz = freq.get(z); if (x == y && y == z) { // All same: C(n, 3) count += fx * (fx - 1) * (fx - 2) / 6; } else if (x == y) { // Two same: C(n, 2) * m count += fx * (fx - 1) / 2 * fz; } else if (x < y && y < z) { // All different count += fx * fy * fz; } } } return (int)(count % MOD); }

// HashMap approach: O(n) time, O(n) space public int[] twoSum(int[] nums, int target) { Map<Integer, Integer> map = new HashMap<>(); for (int i = 0; i < nums.length; i++) { int complement = target - nums[i]; if (map.containsKey(complement)) { return new int[] {map.get(complement), i}; } map.put(nums[i], i); } return new int[] {-1, -1}; } // Two pointers: O(n log n) time, O(1) space // (if array can be sorted and we need values, not indices) public boolean twoSumExists(int[] nums, int target) { Arrays.sort(nums); int left = 0, right = nums.length - 1; while (left < right) { int sum = nums[left] + nums[right]; if (sum == target) return true; else if (sum < target) left++; else right--; } return false; }

// Same pattern as 3Sum, just one more loop public List<List<Integer>> fourSum(int[] nums, int target) { List<List<Integer>> result = new ArrayList<>(); if (nums.length < 4) return result; Arrays.sort(nums); for (int i = 0; i < nums.length - 3; i++) { if (i > 0 && nums[i] == nums[i-1]) continue; for (int j = i+1; j < nums.length - 2; j++) { if (j > i+1 && nums[j] == nums[j-1]) continue; int left = j + 1, right = nums.length - 1; long newTarget = (long)target - nums[i] - nums[j]; while (left < right) { long sum = nums[left] + nums[right]; if (sum == newTarget) { result.add(Arrays.asList( nums[i], nums[j], nums[left], nums[right])); while(left < right && nums[left] == nums[left+1]) left++; while(left < right && nums[right] == nums[right-1]) right--; left++; right--; } else if (sum < newTarget) { left++; } else { right--; } } } } return result; }
