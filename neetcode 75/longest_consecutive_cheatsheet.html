Sort, then walk through counting consecutive diffs of 1, skip duplicates.

The Core Insight

Only start counting a sequence when num−1 does NOT exist in the set. This ensures each sequence is counted exactly once from its true start. The inner while loop runs O(n) total across all iterations — each element is visited at most once — so the overall time is O(n) despite the nested loop.

Code
class Solution {
    public int longestConsecutive(int[] nums) {
        int longest = 0;
        for (int i = 0; i < nums.length; i++) {
            int current = nums[i];
            int count = 1;
            // O(n) scan for each element → O(n²) total
            while (contains(nums, current + 1)) {
                current++;
                count++;
            }
            longest = Math.max(longest, count);
        }
        return longest;
    }

    public boolean contains(int[] nums, int target) {
        for (int n : nums)
            if (n == target) return true;
        return false;
    }
}
class Solution {
    public int longestConsecutive(int[] nums) {
        if (nums.length == 0) return 0;
        if (nums.length == 1) return 1;
        Arrays.sort(nums); // O(n log n)
        int max = 1, sum = 1;
        for (int i = 0; i < nums.length - 1; i++) {
            int diff = nums[i+1] - nums[i];
            // diff==0 → duplicate, skip
            // diff==1 → consecutive, grow
            // else    → gap, reset
            if (diff == 1)      sum++;
            else if (diff != 0) sum = 1;
            max = Math.max(max, sum);
        }
        return max;
    }
}
class Solution {
    public int longestConsecutive(int[] nums) {
        if (nums.length == 0) return 0;
        // Step 1: O(n) insert — also deduplicates
        Set<Integer> set = new HashSet<>();
        for (int n : nums) set.add(n);

        int max = 0;
        for (int n : set) {
            // Step 2: only start from sequence beginning
            if (!set.contains(n - 1)) {
                int len = 1;
                // Step 3: expand — each element visited once total
                while (set.contains(n + len)) len++;
                max = Math.max(max, len);
            }
        }
        return max;
    }
}

10 Interview Questions
Q1 Why check num−1?
Ensures we only start counting from the true beginning of each sequence. Without it, we'd recount the same sequence multiple times — once for each element.
Q2 Why is it O(n) despite the while loop?
Each element is expanded at most once (only from its sequence start). Total expansions across all starts = n. So it's O(n) amortized, not O(n²).
Q3 What about duplicates like [1,2,2,3]?
HashSet automatically deduplicates. Set becomes {1,2,3}. Duplicates have no effect on correctness or performance.
Q4 Does it handle negative numbers?
Yes. [-3,-2,-1,0] works perfectly. HashSet stores any integer. The num−1 check is pure arithmetic, no restrictions.
Q5 Can we reduce space to O(1)?
Sort the array instead — O(n log n) time, O(1) extra space. Trade space efficiency for time efficiency.
Q6 What are the edge cases?
Empty array → 0. Single element → 1. All duplicates [5,5,5] → 1. No consecutive nums → 1. All consecutive → n.
Q7 What if we iterate nums[] vs the set?
Iterating set is cleaner — no re-checking duplicates. Iterating nums[] works too, but the !contains(n−1) guard still fires once per distinct value.
Q8 Sort approach trade-offs?
✓ O(1) space   ✗ O(n log n) time   ✗ Must handle duplicates explicitly (skip when diff = 0). Interviewer prefers HashSet for O(n).
Q9 Why not use a TreeSet?
TreeSet gives sorted order but insert/lookup is O(log n), making total O(n log n). Offers no benefit over sorting + scanning.
Q10 Brute force when is it acceptable?
Only for very small n (n ≤ 100) or quick validation. In production or interviews, always prefer O(n) HashSet or at minimum O(n log n) sort.

Hard Follow-up: Data Stream

★ Numbers arrive as a stream — maintain longest sequence dynamically

Use a HashMap mapping each number to its sequence length. When inserting num:

left = map.getOrDefault(num - 1, 0) // length of sequence ending at num-1 right = map.getOrDefault(num + 1, 0) // length of sequence starting at num+1 total = left + 1 + right // Update boundaries (only ends matter for lookups) map.put(num, total) map.put(num - left, total) // update left boundary map.put(num + right, total) // update right boundary max = Math.max(max, total)

Each insertion is O(1). Space O(n). This is the senior/L5+ follow-up question.
